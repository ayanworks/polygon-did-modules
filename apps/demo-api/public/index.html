Polygon DID Playground

Create, register, resolve and update did:polygon DIDs against the demo API - with or without handing over a key.

1. Identity

A key pair and DID document that the rest of the page operates on. Generate one, or paste your own to reuse.

2. DID document

The document registered on chain. Edit it inline to see updates take effect.

3. Keyless flow no key leaves the browser

The API builds an unsigned transaction, this page signs it locally and posts the signed transaction back. The private key above never reaches the server in this flow.

  1. POST /tx-intent - not started
  2. Sign locally - not started
  3. POST /broadcast - not started
  4. GET /resolve-did - not started
needs testnet POL This address has no funds to pay for the transaction.

The address that signs must hold a little POL on Amoy to cover gas. Your key never leaves this page, so the server cannot top it up for you — fund it from a faucet, then run the flow again.

Fund this address -
Open the Polygon faucet ↗

Faucets give one drip per address per day and can take a minute to land. Any gas-free drip works; the official one is linked above.

4. Resolve

Read the document back from the chain. Works for any DID, including the sample.

5. Custodial flow the key is sent to the API

These mirror the registrar library and exist for demo parity: the server signs on your behalf, so it needs the key. Prefer the keyless flow above for anything real.

Requires the address to hold a little Amoy POL. Get some at faucet.polygon.technology ↗.

6. Credo Module - Schema operations

Use the @ayanworks/credo-polygon-w3c-module (Credo framework integration) to create and fetch schemas on Polygon.

Uses your identity's private key and DID above. The schema is created via the Credo agent using the Polygon module.
